## Actual behavior
- ImagePreview uses the same ClawMediaPreviewState as native tests. Inline data must actually decode with UIImage(data:); with a reference the inline bytes are only a thumbnail, never shareable success. Kingfisher success supplies the decoded full image. The page keeps its black media background; loading/failure disables the explicit 分享 action, retry appears only for a retrievable reference, HTTP 403 uses the permission-specific message, malformed inline data offers return-to-chat without fake download retry.
- A captured Tinode instance, UID, store UID, Cache generation and request generation gate headers and response consumption. No WebSocket-authenticated requirement is added, so retained same-account cached images work offline. Callback UI work is queued on main before the SDK/Cache gate; no waiting for main inside that gate. The existing share helper is passed the original owner explicitly.
- Cache key is a SHA-256 digest over unambiguous JSON of service origin, UID and full media URL. It contains no plaintext token, UID or URL. Original URL-only entries are ignored, not deleted. Each request uses a dedicated ephemeral ImageDownloader so URL-only in-flight coalescing cannot bridge account sessions.
- Same-origin media receives only captured-owner Tinode headers. Direct external HTTPS media (including signed URLs) remains allowed without Tinode headers. User-info URLs, non-network schemes, foreign cleartext HTTP and redirects are rejected in this page. Redirect/CDN-device compatibility is not verified here.
- Sharing exports a PNG representation of the decoded image to temporary ClawImageExports/<fresh UUID>/<safe leaf>. Remote paths never select directories, and a fresh export does not overwrite prior files. This is a share copy; message payload and stored attachment bytes stay unchanged. Animation/original-byte preservation is not promised by this PNG export.
- File picker failures show fixed actionable text to reselect or download locally. File confirmation uses actual filename/type/size and available topic title, explicit 52pt 发送文件 / 取消 controls and accessibility names. The existing send-attachment notification and upload/publish implementation remain. Repeated send taps are disabled locally.
- New failure logs are fixed events only; no remote URL, filename/path or exception text.
